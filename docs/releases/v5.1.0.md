# V5.1.0 stabilization validation record

**Status: stabilization candidate; not a published release.** Product version: V5.1.0. Python package and Docker image candidate version: `0.5.1`. Git tag `v5.1.0` and a GitHub Release are separate publication steps and are not claimed here. This record is updated only with observed evidence.

## Fixed defects

| Defect | Root cause | Correction | Regression evidence |
|---|---|---|---|
| SQLite files could remain open after store reads/writes. On Windows this prevented temporary database directories from being removed. | `sqlite3.Connection` context management commits or rolls back but does not close the connection. | Wrap connection use in a closing context that preserves transaction behavior and always closes the handle. | `test_experiment_store_closes_connections_after_each_operation` captures connections from save/get/list and verifies each rejects use after its operation. |
| Malformed saved model traces could raise an uncaught `AttributeError` during assistant comparison; malformed API provenance could similarly escape as a server error. | Persisted JSON was checked for top-level dictionary shape, but comparison code trusted nested mappings and numeric zone data. | Validate nested provenance, trace and zone shapes before comparing. The API returns HTTP 409 for incompatible or malformed saved data; the assistant provides a deterministic incompatibility response. | `test_assistant_rejects_malformed_saved_experiment_comparison` and malformed API comparison coverage verify safe handling. |
| API and assistant could read different experiment databases when launched from outside the repository root. | The API's default was repository-root-based while the assistant's default was the relative path `reports/experiments.sqlite3`. | Centralize path resolution. Defaults and explicit relative `EXPERIMENT_DB_PATH` values resolve from the repository root; absolute overrides remain absolute. | `test_experiment_database_default_is_shared_and_independent_of_cwd` changes the process CWD, verifies API/assistant share a database, and verifies a relative override. |
| An existing complete Compose volume could fail readiness after the application package version changed. | The diagnostics report was rejected on project-version mismatch, and the initializer refused to update complete persistent volumes. | Validate model bundle fingerprints first, then rerun evaluation/report generation against the existing models if diagnostics are stale. The initializer never retrains or replaces models in this upgrade path. | `test_initializer_refreshes_stale_reports_without_retraining_complete_models` verifies only `scripts/evaluate_model.py` is run after bundle validation. |
| A fresh Compose deployment could not initialize experiment history in its persistent volume. | The volume mounted at `/app/experiments` had no image directory to copy up with app-user permissions; runtime processes run as UID 10001. | Create `/app/experiments` in the Docker image and assign it to `app:app` before mounting the named volume. | Remote container smoke/persistence workflow pending after correction; first failure reproduced in GitHub Actions run `39859768417`. |
| Runtime readiness rejected a freshly trained model bundle with valid SHA-256 metadata. | The validator compared regressor metadata to the classifier artifact after each artifact had already been matched to its own metadata. | Remove the cross-model fingerprint comparison while preserving classifier, regressor, and shared-bundle integrity checks. | `test_runtime_readiness_accepts_fingerprinted_classifier_and_regressor_bundle` covers the valid current bundle shape; existing mismatch tests still fail closed. |

## Improved

- Python package metadata, fallback application version, Docker image tag and OCI image label now use `0.5.1` for product candidate V5.1.0.
- The hashed runtime lock now pins Streamlit `1.66.1`, which supports Pillow `13.0.0`; the obsolete `toml` transitive pin was removed. This resolves the image-build conflict discovered in the first remote CI run.
- The V5.1.0 source patch does not check in, retrain, or replace model artifact files. At runtime, the existing evaluation script can refresh versioned reports and the model-metadata test-metric summary from integrity-validated loaded artifacts.

## Known limitations

- All data, access points, locations, predictions, and capacity scenarios are synthetic. Reported metrics apply only to the documented synthetic evaluation data and are not validated forecasts of real public WiFi usage in Tunja.
- Capacity values are illustrative connection-count proxies, not validated engineering recommendations.
- A successful local Compose parse does not prove Docker build, runtime initialization, service health, HTTP behavior, or volume persistence.

## Compatibility

- No API request or response schema, endpoint, saved experiment schema, or model artifact format changed. The locked Streamlit package was updated for Pillow compatibility; the direct dependency declaration remains unchanged.
- `EXPERIMENT_DB_PATH` continues to select the database. Absolute values behave as before; relative values now resolve from the repository root instead of the current working directory.
- The installed Python package and default Compose image tag advance from `0.5.0` to `0.5.1`. Historical V5.0.0 documentation and metadata remain unchanged.

## Synthetic-data disclaimer

The dataset is synthetic. Access points, coordinates, observations, weather, network indicators, demand labels, and capacity results are simulated. Nothing in this project is verified against real public WiFi measurements or municipal infrastructure in Tunja.

## Publication status

All local quality/security checks and applicable remote container and CI gates have passed, and the results above identify the exact evidence. The annotated `v5.1.0` tag and GitHub Release remain separate publication steps and have not yet been created at this validation-record revision.
