# WiFi Tunja Smart Predictor V4.3.0 — implementation and validation record

**Status: implementation candidate; not a stable release.** The project label is V4.3.0. The Python package and Docker image candidate are `0.4.3`. No `v4.3.0` tag or GitHub Release has been created. Docker runtime and GitHub Actions validation are release gates and remain pending.

All datasets, persisted models, and reported metrics are synthetic. Nothing in this record establishes predictive performance for real public WiFi demand or infrastructure in Tunja.

## Implemented scope

- New training runs persist `artifact_sha256` and `artifact_size_bytes` separately for the classifier and regressor in their model metadata.
- Standard prediction, scenario prediction initialization, runtime readiness, and `scripts/evaluate_model.py` compare available integrity metadata with the same exact bytes deserialized by the inference loader. A partial fingerprint or mismatch is rejected before the artifact is used.
- Metadata created before fingerprint fields existed remains readable for compatibility. Such legacy artifacts remain unverified by fingerprint until retrained; they still must deserialize and pass the existing contract checks.
- V4.2.0 traceability fields, response contracts, model algorithms, feature engineering, and chronological split policy are retained.

## Limitations and release gates

- Docker Desktop's Linux engine was unavailable in the previous audit (`npipe:////./pipe/dockerDesktopLinuxEngine` was missing). Recheck `docker info`; if still unavailable, image build, container health, HTTP smoke, and persistence are BLOCKED.
- Confirm an actual GitHub Actions run for the release commit. A push or an active workflow file alone is not a passing CI result.
- Re-train synthetic model artifacts to populate new fingerprint fields. Older complete volumes without fingerprints remain supported, but their bytes cannot be compared against a stored training-time identity.
- SHA-256 metadata detects changed/corrupted artifact bytes relative to the stored training record; it is not a digital signature and does not authenticate metadata against a malicious rewrite.
- Publish a stable tag/release only after gates pass. Preserve all existing tags; do not infer real-world model validity from synthetic test metrics.
