## Local verification

The following checks passed on the release commit:

- `.venv\Scripts\python.exe -m pytest -q`
- `.venv\Scripts\ruff.exe check .`
- `.venv\Scripts\black.exe --check .`
- `.venv\Scripts\python.exe -m compileall -q api app assistant_api src scripts`
- `git diff --check`
- `docker compose config --quiet`

Docker image build and container runtime/HTTP smoke checks were not run. Docker Desktop's Linux Engine pipe was unavailable in the verification environment. Compose configuration parsing passed, which does not verify image startup or volume behavior in a running container.

After publication, a dashboard responsiveness fix was committed to `main` as `6290cc42d73224a2b15bff8aed1a566628fe1914`. It runs the official-source refresh in a background task and exposes progress while the dashboard remains usable. The annotated `v7.0.0` tag and GitHub Release remain unchanged at the release commit above and do not include this follow-up commit.

The official MinTIC API was queried live during implementation. The Tunja snapshot retrieved 16,926 source rows, accepted 15,122 normalized unique records, and rejected 1,804 exact duplicates. It covered 2023-Q4 through 2026-Q2 at the time of retrieval. These fixed-access records are municipality-level source aggregates, not public WiFi telemetry, unique people, simultaneous users, measured throughput, or evidence of congestion or saturation. Existing model training and evaluation continue to use synthetic data only.

CRC Postdata QoE dashboards and ONTIC catalog/geoportal were researched and registered as references. A stable structured Tunja feed or layer was not verified for integration. The requested Data Flash PDF URL was unavailable during research. No real-data model or saturation proxy was added.
