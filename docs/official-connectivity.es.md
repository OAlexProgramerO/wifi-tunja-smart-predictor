# Datos oficiales de conectividad (V7.3.0)

## Fuente integrada

La primera fuente estructurada es el conjunto MinTIC / Datos Abiertos [Accesos Fijos a Internet por Proveedor, Departamento, Municipio, Tecnología, Segmento y ancho de banda](https://www.datos.gov.co/Ciencia-Tecnolog-a-e-Innovaci-n/Accesos-Fijos-a-Internet-por-Proveedor-Departament/hwrp-3su3), ID Socrata `hwrp-3su3`. La API JSON oficial es `https://www.datos.gov.co/resource/hwrp-3su3.json`; los metadatos están en `https://www.datos.gov.co/api/views/hwrp-3su3.json`.

Los metadatos identifican a MinTIC, describen registros trimestrales, códigos municipales DIVIPOLA y la licencia de catálogo `CC_40_BY_SA` (Creative Commons Atribución-CompartirIgual 4.0). Los campos observados incluyen año, trimestre, proveedor, nombres y códigos departamentales y municipales, segmento, tecnología, velocidad de bajada, velocidad de subida y accesos fijos. El catálogo describe las velocidades en Mbps y los accesos como conexiones presentes al último día del trimestre. Durante la investigación, el catálogo indicaba una actualización de filas el 26-10-2026; cada actualización captura la marca vigente cuando está disponible.

Tunja se filtra mediante el código municipal DIVIPOLA `15001` (departamento `15`). La granularidad es municipal. No hay barrios, ubicaciones de puntos de acceso, calles, tráfico, usuarios simultáneos, latencia, jitter ni mediciones directas de congestión o saturación. El dashboard no crea marcadores ni mapas de barrios a partir de estos registros.

## Ingestión e instantáneas locales

Ejecute `python scripts/refresh_official_data.py`. El conector consulta los metadatos, verifica el ID y campos requeridos, recupera JSON en páginas de 50 000 con tiempos límite y reintentos acotados para errores de límite o servidor, filtra Tunja por código DIVIPOLA desde la fuente y cuenta filas rechazadas por motivo. El token opcional `SOCRATA_APP_TOKEN` se lee del entorno y nunca se registra. Si `rowsUpdatedAt` coincide con la última instantánea válida, evita descargar nuevamente las filas. Si el catálogo no proporciona esa fecha, vuelve a consultarlas; aún no usa ETag HTTP.

Por defecto, guarda las instantáneas en `data/official_connectivity.sqlite3`; `OFFICIAL_DATA_DB_PATH` permite elegir otra ruta local. Git ignora esta base de datos. Cada lote registra ID y URL de fuente, ID de conjunto, hora de recuperación, actualización de fuente, SHA-256 de la respuesta cruda completa, conteos recuperados/aceptados/rechazados, estado de validación y versión de transformación. Cada fila aceptada se conserva como JSON crudo y normalizado separados. Una actualización fallida, vacía o completamente inválida no reemplaza el último lote válido. Si la actualización falla, API y dashboard pueden usar la última instantánea válida e indicar el estado de caché. Se marca como obsoleta tras 30 días; es un umbral operativo, no una frecuencia de actualización atribuida al publicador.

La versión `mintic-tunja-fixed-access-v1` conserva campos originales y normaliza código municipal, trimestre, bandas enteras de velocidad y accesos informados. Rechaza filas duplicadas exactas. Son agregados publicados, no observaciones por hogar. Las bandas se muestran como las informa la fuente; no se reinterpretan como rendimiento medido por usuario.

## Análisis y límites

El dashboard y `GET /connectivity/tunja` muestran conteos de accesos por proveedor, tecnología, trimestre y valores informados de bajada/subida. Los gráficos por proveedor y tecnología usan el último trimestre; la tendencia muestra totales trimestrales. Los agregados multianuales se identifican como sumas de filas trimestrales repetidas, no como suscriptores únicos. La API incluye huella, tiempos de recuperación/actualización, conteos y motivos de rechazo, y versión de transformación. `GET /connectivity/sources` lista el registro e identifica qué fuentes están integradas y cuáles son solo referencias.

Durante la verificación del 05-11-2026, la consulta oficial de Tunja devolvió 16 926 filas: se aceptaron 15 122 filas únicas y se rechazaron 1 804 duplicados exactos. La instantánea cubrió 2023-T4 a 2026-T2; el último trimestre sumó 58 954 en el campo de accesos de las filas agrupadas aceptadas. No representa personas únicas, usuarios simultáneos, clientes WiFi ni saturación. Los metadatos indicaron actualización de filas a las 2026-10-26T13:59:28Z. Un refresh posterior podría cambiar estos conteos.

No se calcula un puntaje de presión ni de saturación. Más suscripciones no prueban congestión y una banda informada no prueba el rendimiento experimentado. El conjunto no contiene tráfico, utilización, disponibilidad ni verdad de terreno de saturación. Los modelos existentes siguen entrenados solo con datos sintéticos; no se combinan ejemplos sintéticos con esta fuente y ningún modelo predice condiciones reales de red.

## Exportar registros y análisis oficiales (V7.1.0)

El expander **Export official connectivity data** está disponible cuando se puede leer una instantánea local validada. El CSV incluye una fila de metadatos y luego registros aceptados. Cada registro conserva el JSON original de la fuente en `raw_source_record_json` y separa los campos normalizados en columnas `processed_*`. El JSON separa `raw_records`, `processed_records`, `analysis` agregada, metadatos de la fuente y procedencia del lote. Ambos formatos incluyen la distinción entre datos reales y sintéticos, institución, nombre y URL oficial, ID del conjunto, horas de recuperación/actualización, periodos, granularidad municipal, conteos y estado de validación cuando están disponibles.

Los valores crudos se conservan sin cambios dentro del JSON de origen. Los valores procesados normalizan trimestre y códigos DIVIPOLA, limpian texto y convierten las bandas de velocidad informadas a números en Mbps; siguen siendo categorías reportadas, no mediciones de rendimiento por usuario. El análisis conserva la semántica de agregación existente, incluida la identificación de sumas repetidas por trimestre. Las filas normalizadas incompletas se exportan con estado explícito; se omite el análisis agregado si faltan campos necesarios. Las instantáneas vacías aún permiten exportar metadatos y análisis vacío. Sin una instantánea local válida, las descargas no están disponibles hasta completar una actualización. Si una caché supera 30 días, JSON y la fila de metadatos CSV la identifican como `stale_local_snapshot`; las exportaciones describen datos recuperados localmente y nunca afirman que la fuente está conectada en vivo.

## Historial de actualizaciones (V7.2.0)

Cada intento se agrega a `connectivity_refresh_attempts` en la misma base SQLite local. El snapshot exitoso y su fila de historial se confirman en una misma transacción. Los fallos guardan un tipo de error sanitizado y el conteo/periodo recuperados cuando se conocen; la instantánea válida anterior se conserva. Una consulta que confirma que la fuente no cambió cuenta como intento exitoso, con validación `unchanged_source` y cero filas nuevas descargadas.

`GET /connectivity/refresh/latest` separa el último intento y el último intento exitoso de la instantánea disponible localmente. `GET /connectivity/refresh/history?limit=20&offset=0` pagina en orden descendente, con máximo de 100 filas por página. El dashboard muestra los errores del intento por separado del estado de caché. Los estados posibles son `cached_local`, `stale_cached` o `unavailable`; “cached” significa que los datos se leyeron del almacenamiento local, no que se haya consultado la fuente en ese momento. Una instantánea de más de 30 días se marca obsoleta. Las bases SQLite anteriores sin la tabla de historial siguen siendo legibles; antes de la primera actualización, la API devuelve historial vacío e informa por separado si hay una instantánea disponible.

## Comparar periodos oficiales (V7.3.0)

Los selectores del dashboard y `GET /connectivity/tunja/compare` usan solo filas normalizadas completas de la instantánea local validada. Elija dos periodos realmente disponibles; la API devuelve `period_unavailable` si falta alguno. No interpola ni reconstruye historia. Compara totales de accesos informados y conteos agrupados por proveedor, tecnología y banda de velocidad informada de bajada/subida. La diferencia absoluta es comparación menos base. El cambio porcentual es `diferencia / base × 100` solo cuando la base no es cero. Una categoría ausente en un periodo permanece no disponible, no se interpreta como cero; las filas incompletas o inválidas se omiten y cuentan.

Son cambios de agregados municipales de accesos fijos, no de suscriptores únicos ni tráfico WiFi. Los cambios en suscripciones no miden congestión ni saturación. No se introduce un modelo o predicción con datos reales; los modelos existentes siguen siendo sintéticos.

## Otras referencias oficiales revisadas

- CRC [Postdata](https://www.postdata.gov.co/) describe un tablero QoE fijo con varios periodos por operador, ciudad y departamento, basado en crowdsourcing de Ookla Speedtest; su tablero móvil describe cinco indicadores cronológicos por operador, 3G/4G, municipio y algunas localidades/comunas, obtenidos mediante crowdsourcing de dispositivos. Los tableros oficiales son [fijo](https://www.postdata.gov.co/dashboard/mediciones-de-calidad-desde-la-experiencia-del-usuario-internet-fijo) y [móvil](https://www.postdata.gov.co/dashboard/mediciones-de-calidad-desde-la-experiencia-del-usuario-internet-movil). No se verificó para esta versión una descarga estructurada de Tunja ni una API estable, por lo que sus valores QoE no se integran.
- La URL indicada del [Data Flash 2025-016 de calidad fija](https://www.postdata.gov.co/sites/default/files/dataflash/Data%20Flash%202025-016%20QoE%20Fijo%20Jun.2025.pdf) no estaba disponible (404 al verificar). Se conserva como referencia de informe, no como fuente continua.
- El [catálogo TIC de ONTIC](https://ontic.mintic.gov.co/portal/Secciones/Catalogo-de-Datos/Datos-TIC/) lista archivos trimestrales nacionales y recursos CSV/JSON históricos. El [geoportal](https://ontic.mintic.gov.co/portal/Secciones/Geoportal/) tiene un visor nacional de conectividad actualizado el 03-09-2026 y enlaza una experiencia ArcGIS. No se validó en este cambio una capa de Tunja suficientemente documentada o una descarga legible y manejable; ONTIC queda registrado para investigar, pero no integrado.

La fuente integrada trata de accesos de banda ancha fija, no de telemetría WiFi pública. El análisis futuro de calidad requiere datos estructurados accesibles con ubicación y periodo documentados para Tunja. El análisis barrial requiere observaciones oficiales a esa escala o mediciones locales autorizadas por separado.
