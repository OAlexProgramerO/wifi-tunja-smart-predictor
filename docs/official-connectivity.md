# Official Connectivity Data (V7.1.0)

## What is integrated

The first structured source is the MinTIC / Datos Abiertos dataset [Accesos Fijos a Internet por Proveedor, Departamento, Municipio, Tecnología, Segmento y ancho de banda](https://www.datos.gov.co/Ciencia-Tecnolog-a-e-Innovaci-n/Accesos-Fijos-a-Internet-por-Proveedor-Departament/hwrp-3su3), Socrata ID `hwrp-3su3`. Its official JSON API is `https://www.datos.gov.co/resource/hwrp-3su3.json`; metadata is `https://www.datos.gov.co/api/views/hwrp-3su3.json`.

Source metadata identifies MinTIC as the institution, describes quarterly records, cites DIVIPOLA municipality codes, and labels the catalog license `CC_40_BY_SA` (Creative Commons Attribution-ShareAlike 4.0). The observed fields are `anno`, `trimestre`, `proveedor`, department and municipality names/codes, `segmento`, `tecnologia`, `velocidad_bajada`, `velocidad_subida`, and `accesos_fijos_internet`. The catalog describes speed values in Mbps and access counts as connections present on the final day of the reported quarter. Catalog metadata reported a row update on 2026-10-26 during implementation research; a refresh captures the source's current timestamp when available.

Tunja is selected by municipality DIVIPOLA code `15001` (department code `15`). The source is municipality-level. It contains no neighborhood IDs, AP locations, street-level data, traffic, simultaneous users, latency, jitter, or direct congestion/saturation measurements. The dashboard does not render neighborhood pins or maps from these records.

## Ingestion and local snapshots

Run `python scripts/refresh_official_data.py`. The connector requests source metadata, verifies the dataset ID and required field names, retrieves JSON in pages of 50,000 with request timeouts and bounded retry for rate-limit/server errors, filters on Tunja's DIVIPOLA code at the source, and records rejected row counts by reason. Optional `SOCRATA_APP_TOKEN` is read from the environment and never logged. If the catalog's `rowsUpdatedAt` value matches the last valid snapshot, the potentially large row download is skipped. If the catalog does not supply that timestamp, data are retrieved again; no HTTP ETag check is implemented.

By default snapshots are stored in `data/official_connectivity.sqlite3`; set `OFFICIAL_DATA_DB_PATH` to choose another local path. The database is intentionally ignored by Git. Each batch records source ID, API URL, dataset ID, retrieval time, source update time, SHA-256 of the complete raw response, retrieved/accepted/rejected counts, validation status, and transformation version. Each accepted Tunja row has separate raw JSON and normalized JSON. A failed, empty, or wholly invalid refresh does not replace the previous valid batch. On refresh failure, API and dashboard reads can continue from the most recent valid snapshot and label the refresh/cache status. Cache is marked stale after 30 days; this is an operational warning threshold, not a claim about the publisher's update schedule.

Normalization version `mintic-tunja-fixed-access-v1` preserves original raw fields and normalizes municipality code, quarter, integer speed bands, and reported access counts. Exact duplicate source rows are rejected. The data are published aggregates, not household-level observations. Speed bands are grouped as reported; they are not reinterpreted as measured user throughput.

## Analysis and interpretation

The dashboard and `GET /connectivity/tunja` report source access-count totals grouped by provider, technology, quarter, and reported downstream/upstream values. Provider and technology charts use the latest reporting quarter; the trend shows quarterly totals. All-period aggregates are explicitly identified as sums of repeated quarterly rows, not unique subscribers. The API includes source fingerprint, retrieval/source-update times, accepted/rejected counts and reasons, and transformation version. API `GET /connectivity/sources` lists the registry and distinguishes integrated data from references that are not ingested.

During release verification on 2026-11-05, the live source query for Tunja returned 16,926 rows: 15,122 unique rows accepted and 1,804 exact duplicates rejected. The snapshot covered 2023-Q4 through 2026-Q2; the latest quarter's source access-count column summed to 58,954 across its accepted grouped rows. This is not a count of unique people, simultaneous users, WiFi clients, or saturation. Source metadata reported a row update at 2026-10-26T13:59:28Z. A later refresh may return different counts.

No connectivity-pressure or saturation score is calculated. An increase in subscriptions does not establish congestion, and a reported speed band does not establish achieved performance. The dataset has no traffic, utilization, availability, or direct saturation ground truth. The existing ML classifiers and regressors remain trained on synthetic data only; no synthetic examples are joined to this official dataset and no model predicts real network conditions.

## Exporting official records and analysis (V7.1.0)

The **Export official connectivity data** expander is available when a validated local snapshot can be read. CSV contains a metadata row followed by accepted records. Each record keeps the original source JSON in `raw_source_record_json` and puts normalized fields in separate `processed_*` columns. The JSON export separates `raw_records`, `processed_records`, aggregate `analysis`, source metadata, and batch provenance. Both exports include real-versus-synthetic classification, source institution/name/URL, dataset ID, retrieval/source-update timestamps, reporting periods, municipality granularity, record counts, and validation state where available.

Raw values are preserved unchanged in the source JSON. Processed values normalize quarter and DIVIPOLA codes, clean text, and convert source speed-band values to numeric Mbps; these bands remain reported categories and are not measurements of user throughput. The analysis keeps the existing aggregation semantics, including marking repeated-quarter sums as such. Incomplete normalized rows are included with an explicit incomplete status; aggregate analysis is withheld if required fields are missing. Empty snapshots still produce metadata and empty analysis exports. If no valid local snapshot exists, downloads are unavailable until a refresh succeeds. A cached snapshot older than 30 days is marked `stale_local_snapshot` in JSON and in the CSV metadata row; exports describe locally retrieved data and never claim a live source connection.

## Other official references checked

- CRC [Postdata](https://www.postdata.gov.co/) describes a fixed QoE dashboard with multiple periods by operator, city, and department, based on Ookla Speedtest crowdsourcing; its mobile QoE dashboard describes five chronological indicators by operator, 3G/4G, municipality, and some localities/communes, based on operator-contracted crowdsourcing from user devices. The dashboards are [fixed](https://www.postdata.gov.co/dashboard/mediciones-de-calidad-desde-la-experiencia-del-usuario-internet-fijo) and [mobile](https://www.postdata.gov.co/dashboard/mediciones-de-calidad-desde-la-experiencia-del-usuario-internet-movil). An underlying machine-readable Tunja feed/export and stable API were not verified for this release, so no QoE values are represented as integrated data.
- The specified [Data Flash 2025-016 fixed QoE PDF](https://www.postdata.gov.co/sites/default/files/dataflash/Data%20Flash%202025-016%20QoE%20Fijo%20Jun.2025.pdf) URL was unavailable (404 during verification). It remains a report/reference, not a data feed.
- ONTIC's [TIC data catalog](https://ontic.mintic.gov.co/portal/Secciones/Catalogo-de-Datos/Datos-TIC/) lists quarterly Colombia-wide workbooks and historical CSV/JSON resources. Its [geoportal](https://ontic.mintic.gov.co/portal/Secciones/Geoportal/) includes a national connectivity viewer updated 2026-09-03, with an ArcGIS Experience Builder link. No appropriately documented Tunja layer or manageable machine-readable export was validated for this change, so ONTIC is registered for future investigation but not integrated.

The integrated source is fixed broadband access, not public WiFi telemetry. Future service-quality work requires accessible structured data with documented Tunja location and reporting periods. Neighborhood analysis requires official neighborhood-granularity observations or separately authorized local measurement data.
